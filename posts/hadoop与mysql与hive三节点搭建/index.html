搭一套大数据集群，听起来很复杂，其实可以把它想象成组建一个三人小团队：一个人负责调度（主节点 master），两个人负责干活（从节点 slave1、slave2）。三个人要互相认识（主机名与 hosts）、有统一的作息（时间同步）、能无障碍沟通（免密登录），还要各司其职（Hadoop 负责存储与计算，MySQL 负责保管元数据，Hive 负责把 SQL 翻译成计算任务，Flume 负责搬数据）。这篇文章就按真实的搭建顺序，把每一步的命令、配置和排错方法完整写下来，照着做就能得到一套可用的三节点环境。

vim 编辑器常用操作

配置文件基本都要用 vim 修改，先记住下面这些高频操作（注意输入时切换到英文状态）：

  • 模式切换：普通模式下按 i 或 Insert 进入编辑模式；按 Esc 回到普通模式。
  • 搜索：普通模式下输入 /关键词（如 /User），按 n 跳到下一个匹配，搜到末尾会从头继续。
  • 保存退出：:wq 表示保存并退出（write + quit）；只保存用 :w；不保存强制退出用 :q!（! 表示强制）。
  • 快速定位：普通模式下按大写 G 跳到文件末尾，连按两次小写 g（即 gg）跳到文件开头。
  • 可视模式：普通模式按 v 进入 visual 模式，用 h/j/k/l 或方向键选中文本，按 y 复制、p 粘贴。
  • 行操作：dd 删除整行，yy 复制整行，p 粘贴，h/j/k/l 移动光标。

排错：遇到带 0x8 的报错

初始化时常见的报错信息里会带 0x8 字样，原因是默认配置中有一段 &#8; 控制字符导致解析失败。处理办法：

  1. 在 hive-site.xml 里跳到第 3215 行（命令模式输入 :3215）；
  2. 或者搜索 /&# 定位到那一行；
  3. 把 <description>...</description> 里包含 &#8; 的整行删掉。<description> 只是给人看的说明，程序不会读取，用 dd 整行删除即可。

改完保存后重新执行初始化命令即可。成功后就可以用图形化客户端（如 Navicat）从 Windows 连接这台 MySQL 了。

小结

到这里，一套完整的三节点大数据环境就搭起来了：三台机器通过主机名和免密登录连成整体，Hadoop 负责分布式存储与计算，MySQL 保管 Hive 元数据，Hive 提供类 SQL 查询，Flume 负责日志采集，几个文本命令完成了数据清洗。回顾整个过程，最容易出错的地方集中在三处——环境变量 PATH、Hadoop 核心配置文件的 XML 结构、以及 MySQL 初始化参数。遇到问题时按”先看进程（jps）、再看日志、最后核对配置”的顺序排查，绝大多数故障都能定位。基础环境准备好之后，想进一步了解如何让集群避免单点故障，可以继续阅读《hadoop高可用集群搭建》一文。
