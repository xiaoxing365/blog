在一大段文字里找出所有手机号、把日志里的 IP 全部提取出来、把重复空格压缩成一个——这些活靠手工做又慢又容易漏，正则表达式就是专门干这个的。它看起来像一串”天书”，但拆开看只有元字符、量词、分组等几个零件。本文先给速查表，再用 Python 的 re 模块把每个用法跑一遍。

一、元字符速查表

元字符是正则表达式里有特殊含义的字符。记住这张表，就看懂了一大半：

元字符 含义 示例
. 匹配除换行外的任意单个字符 .ar 可匹配 car、jar
^ 匹配字符串开始 ^abc 匹配以 abc 开头
$ 匹配字符串结束 at\.$ 匹配以 at. 结尾
* 前面元素出现 0 次或多次 a* 匹配空、a、aaa
+ 前面元素出现 1 次或多次 c.+t 匹配 c 开头 t 结尾
? 前面元素出现 0 次或 1 次 [T]?he 匹配 The 和 he
[abc] 字符集中的任意一个 [Tt]he 匹配 The、the
[^abc] 不在字符集中的任意字符 [^C] 匹配非 C 字符
[a-z] 范围内的任意小写字母 [0-9] 匹配一个数字
\s 任意空白字符（空格、制表、换行） \s+ 匹配一段空白
\S 任意非空白字符 —
\d 数字，等价 [0-9] (digit) \d{3} 匹配三位数字
\D 非数字 —
\w 字母、数字、下划线，等价 [A-Za-z0-9_] (word) \w+ 匹配一个单词
\W 非单词字符 —
[\s\S] 任意字符，包括换行 常用于跨行匹配

一个规律：小写表示”匹配”，大写表示”取反”，例如 \d 匹配数字，\D 匹配非数字。方括号里的 ^ 不再表示开头，而是”排除”的意思。

二、量词与贪婪

量词用来指定某个元素重复多少次：

写法 含义
{n} 正好 n 次
{n,} 至少 n 次
{n,m} 至少 n 次，最多 m 次
* 0 次或多次，等价 {0,}
+ 1 次或多次，等价 {1,}
? 0 次或 1 次，等价 {0,1}

例如 [0-9]{2,3} 匹配 2 到 3 位数字；[0-9]{2,} 匹配至少 2 位；[0-9]{2} 匹配正好 2 位。

2.1 贪婪与非贪婪

默认情况下，量词是贪婪的——尽可能多匹配。在量词后面加 ? 就变成非贪婪，尽可能少匹配。这个区别在处理成对标签时特别明显：

贪婪模式下，.+ 一路吃到最后一个 </b> 才停；加上 ? 后，遇到第一个 </b> 就收手。需要”最短匹配”时记得加这个问号。

4.2 四种断言

断言（lookaround）只检查”前后是否满足条件”，本身不消耗字符，所以叫”零宽”。它们像站在某个位置向前后张望：

负向先行 (?!...) 后面不能跟着某内容
正向后行 (?<=...) 前面必须是某内容
负向后行 (?<!...) 前面不能是某内容

五、Python re 模块逐个演示

使用正则要先导入模块：import re。下面把常用方法逐个跑一遍。

5.1 re.split：按模式分割

maxsplit 参数限制最大分割次数，不写就是全部分割。

5.2 re.findall：找出所有匹配

返回所有匹配结果的列表，是最常用的方法之一。

5.3 re.sub：替换

三个参数依次是”模式、替换内容、原字符串”。花括号在正则里有含义，匹配字面量时要转义成 \{ 和 \}。

5.4 re.subn：替换并计数

想知道”到底改了几处”时，用 subn 比 sub 方便。

5.5 re.escape：转义特殊字符

当用户输入的内容要当作普通文本参与匹配时，先用 escape 处理，避免里面的 +、. 被当成元字符。

5.6 re.match：从开头匹配

match 只检查字符串开头，开头不匹配就直接返回 None。注意它和 search 的区别——search 会在整段文字里找，即使目标不在开头也能找到。

5.7 re.search：任意位置查找

search 会在整个字符串里找第一个匹配位置。用 group(1)、group(2) 可以按括号顺序取出各个分组捕获的内容。

5.8 re.compile：预编译

同一条正则要反复使用时，先用 compile 编译成 Pattern 对象，后续直接调用它的方法，既简洁又高效。

七、常见坑与练习建议

写正则时新手最容易踩三个坑：

  1. 忘记用原始字符串。r'\d+' 和 '\d+' 在多数情况下结果相同，但碰到 \b、\1 这类写法时，普通字符串会先被 Python 解释一次，导致匹配失败。养成加 r 前缀的习惯，能省掉很多莫名其妙的问题。
  2. 贪婪匹配切得太多。用 .* 提取成对标签时，往往一路匹配到最后一个结束标签。先问自己要”最长”还是”最短”，要最短就加 ?。
  3. 不清楚断言是否消耗字符。断言只判断位置、不把内容放进结果，所以 (?=元) 匹配到的数字不包含”元”字。如果想连单位一起取，就把单位写进匹配模式，而不是放在断言里。

练习建议：先拿一段日志练 findall，把 IP 和时间提取出来；再用 sub 把敏感字段替换成占位符；最后把常用模式用 compile 封装起来复用。写法上先求”能跑通”，再逐步收紧条件，不必一上来就追求一条表达式解决所有问题。

小结

正则表达式的零件其实不多：元字符定义”匹配什么”，量词定义”匹配几次”，分组定义”把谁当整体”，定位符与断言定义”在哪儿匹配”。写复杂表达式时别急着一次成型，先用最简单的模式跑通，再逐步加条件。在 Python 里，查找用 findall/search，替换用 sub/subn，分割用 split，反复使用就 compile。记住多用原始字符串 r'...'，遇到贪婪问题先想想该不该加 ?，正则就会从”天书”变成趁手的工具。
