如果说操作系统是一栋大楼，文件系统就是房间的布局，权限则是每扇门上的锁。理解 Linux 的目录结构，再理解”谁有钥匙、能开哪扇门”，你就掌握了这套系统最核心的秩序。这一篇就把这两件事讲清楚。

Linux 文件系统：一棵倒过来的树

Linux 把所有文件组织成一棵树，树根是 /，称为根目录。之所以说是”倒过来的树”，是因为根在最上面，分支向下展开。Windows 有 C 盘、D 盘多个根，Linux 只有这一个根，其他分区和设备都要”挂”到这棵树的某个目录上才能访问，这个目录叫挂载点。

从根目录看常见的家目录

根目录下有一批约定俗成的子目录，各自承担固定职责：

目录 用途
/bin 所有用户都能用的基础命令
/boot 启动系统所需的文件
/dev 设备文件，比如硬盘、终端
/etc 系统配置文件
/home 普通用户的家目录
/lib 系统库文件
/media、/mnt 临时挂载点，U 盘、移动硬盘常出现在这里
/opt 额外安装的软件
/proc 进程与内核信息的虚拟目录
/root 管理员 root 的家目录
/sbin 系统管理专用命令
/tmp 临时文件，重启后常被清空
/usr 用户程序与文档
/var 经常变化的数据，如日志、缓存

路径的写法分两种。以 / 开头、从根目录一路写下来的叫绝对路径，比如 /home/alice/notes.txt；从当前目录开始写的叫相对路径，比如 notes.txt 或 ../notes.txt。其中 . 表示当前目录，.. 表示上一级目录，~ 代表当前用户的家目录，这几个符号在命令里会频繁出现。

用户与用户组：权限体系的主角

Linux 是天生的多用户系统。每个使用者都是一个”用户”，系统用数字 UID 来唯一标识；每个用户可以属于一个或多个”用户组”，组用 GID 标识。把用户分组，是为了批量分配权限更方便。

有几类角色需要认识：

  • root 用户：UID 为 0 的超级管理员，拥有系统的最高权限，能读写任何文件、执行任何操作。
  • 普通用户：UID 通常从 1000 开始，权限受限，只能操作自己的文件和被授权的内容。
  • 系统用户：UID 一般在 1 到 999 之间，给系统服务使用，通常不允许登录，比如 www-data、nobody。

用户信息主要存放在 /etc/passwd，组信息存放在 /etc/group，密码哈希存放在 /etc/shadow。这三个文件构成了账户体系的基础，后面讲用户管理命令时会反复用到。

rwx 权限到底代表什么

每个文件和目录都有三组权限，分别对应三类对象：

  • u（user）：文件所有者。
  • g（group）：文件所属组里的用户。
  • o（others）：既不是所有者、也不在所属组的其他人。

每组权限又由三个字符组成：

  • r（read，读）：对文件表示能查看内容；对目录表示能列出里面的文件名。
  • w（write，写）：对文件表示能修改内容；对目录表示能在其中创建、删除、改名。
  • x（execute，执行）：对文件表示能当作程序或脚本运行；对目录表示能进入该目录（比如 cd 进去）。

要解决什么：想看清某个文件当前的权限设置，判断自己能不能读、写、执行它。

解读第一列 -rw-r--r--：开头的 - 表示这是普通文件（目录则是 d）；接下来三个字符 rw- 是所有者权限，表示可读可写不可执行；再三个 r-- 是所属组权限，只读；最后三个 r-- 是其他人权限，也是只读。预期效果：你能从这一列直接读出三类对象各自的权限，这是排查”为什么改不了文件”的第一步。

数字权限 755、644、777 速查

除了 rwx 这种字母写法，权限还常用三位八进制数字表示。规则很简单：r 记为 4，w 记为 2，x 记为 1，没有权限记为 0，把一组内的三个值相加就得到这一组的数字。

  • rwx = 4+2+1 = 7
  • rw- = 4+2+0 = 6
  • r-x = 4+0+1 = 5
  • r-- = 4 = 4
  • --- = 0

三组数字连起来，就是常见的权限码：

数字 字母表示 含义与典型用途
755 rwxr-xr-x 所有者可读写执行，其他人可读可执行；常用于程序、脚本、目录
644 rw-r–r– 所有者可读写，其他人只读；常用于普通文档、配置文件
777 rwxrwxrwx 所有人可读写执行；权限过宽，一般不建议随意使用
600 rw——- 仅所有者可读写；适合存放敏感文件
700 rwx—— 仅所有者可读写执行；适合私有目录

记住 755 和 644 这两个就够应付大多数场景：程序、脚本、需要进入的目录用 755，普通文件用 644。看到有人图省事 chmod 777，要意识到它等于把门敞开给所有人。

用户和组的管理命令

管理账户会用到下面这组命令，整理成表格方便速查：

命令 作用 常用写法
useradd 创建用户 useradd -m alice
passwd 设置或修改密码 passwd alice
userdel 删除用户 userdel -r alice
groupadd 创建组 groupadd devteam
usermod 修改用户属性 usermod -aG devteam alice

几个常用的参数值得单独说明：

  • useradd -m：创建用户的同时建立家目录，不加这个参数新用户可能没有家目录。
  • useradd -s /bin/bash：指定用户登录后使用的 Shell。
  • userdel -r：删除用户的同时删除其家目录和邮件，避免留下残留数据。
  • usermod -aG 组名 用户名：把用户追加到某个附加组。这里的 -a（append）非常关键，省略它会把用户从其他附加组里移除，造成意外后果。

要解决什么：新建一个用户，给他家目录和登录 Shell，再把他加入开发组。

预期效果：用 id alice 查看，能看到她的 uid、gid 以及所属的所有组，确认配置生效。

Root 与 sudo：安全地获得管理员权限

root 是系统的超级管理员，拥有完全控制权。日常直接以 root 登录非常危险：一个误操作，比如敲错一个删除命令，就可能让系统无法启动。因此 Linux 世界有一条基本原则——最小权限原则：平时用普通账户，只在需要时临时提升权限。

sudo 是如何工作的

sudo（superuser do）允许受信任的普通用户以 root 身份执行指定命令，且无需知道 root 密码。它的好处是可审计：每次 sudo 使用都会留下日志，便于追溯。给普通用户授权，推荐的做法是把他加入预设的管理组，而不是逐个用户去配置。

不同发行版的管理组名字不同：

  • CentOS / RHEL 系列：wheel 组。
  • Ubuntu / Debian 系列：sudo 组。

要解决什么：让普通用户 alice 获得管理员权限，但不用把 root 密码告诉她。

id 命令会列出用户的 uid、gid 和所属组。预期效果：输出中出现 wheel 或 sudo 字样，就说明加组成功。注意用户需要重新登录，新的组关系才会生效。

执行 sudo 时，系统会要求输入当前用户的密码（不是 root 密码），验证通过后在一段时间内免重复输入。sudo -i 会直接开启一个 root Shell，权限过大且容易忘记退出，因此只在确实需要连续执行多条管理命令时短期使用，做完立刻 exit 退回普通用户。

从目录结构到权限位，再到 root 与 sudo，这套机制的核心思想其实只有一句：让每个用户只拿到刚好够用的权限。把 755 和 644、把 usermod -aG 和 visudo 这几个知识点记牢，你就能在日常使用中既把事情办成，又不给系统埋下安全隐患。
