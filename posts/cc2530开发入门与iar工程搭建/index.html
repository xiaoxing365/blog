你家里可能有一个温湿度传感器，隔一会儿就把数据发给网关；也可能有一个无线开关，按一下就能控制灯。这些小设备里往往藏着一颗功耗极低的无线主控芯片，CC2530 就是其中最经典的一颗。它把 8051 处理器和 2.4GHz 无线收发器做在同一块硅片上，是 Zigbee 设备最常见的”大脑”。要把想法变成能跑的程序，第一步是认识它的引脚，第二步是把开发环境搭起来。

认识 CC2530 无线主控芯片

CC2530 由德州仪器（Texas Instruments，简称 TI）推出，内部是一颗增强型 8051 内核，外加一个符合 IEEE 802.15.4 标准的 2.4GHz 射频收发器。Zigbee 协议的物理层和媒体访问控制层就跑在这颗射频模块上，所以我们常把它叫作”Zigbee 芯片”。

按片内 Flash 容量，CC2530 分为 F32、F64、F128、F256 几个版本，数字代表闪存大小。本系列开发使用的是 CC2530F256，也就是 256KB Flash 的版本，空间足够容纳 Zigbee 协议栈和应用程序。芯片运行时以 32MHz 晶振作为主时钟，并配有一颗 32.768kHz 的低频晶振用于休眠计时。

初学阶段可以先把它当成一个”带无线功能的普通单片机”：写代码控制引脚高低电平、读按键、用定时器计时、通过串口打印信息，这些操作和学 51 单片机时基本一致。等基础打牢，再研究无线收发部分。

P0、P1、P2 三组通用 IO 端口

芯片与外部世界打交道，靠的是一个个引脚。CC2530 把引脚分成 P0、P1、P2 三组，每组最多 8 个，命名成 P0_0 到 P0_7 这样的形式。不过并不是所有引脚都能随意使用。

端口 可用引脚 说明
P0 P0_0 至 P0_7，共 8 个 全部可作通用 IO，其中个别引脚常与调试功能复用
P1 P1_0 至 P1_7，共 8 个 全部可作通用 IO，是点灯、读按键最常用的端口
P2 P2_0 至 P2_4，共 5 个 其中部分引脚默认用于仿真调试和晶振，实际可用的很少

P2 端口只有 5 个引脚，而且这 5 个里有 2 个被仿真调试占用、2 个用来接晶振，因此真正能腾出来给用户使用的通用 IO 大约只有 17 个。这也是为什么点灯和按键实验几乎都集中在 P0 和 P1 上。刚上手时不必纠结每一个引脚的去向，照着电路图给出的连接关系使用即可；等熟悉了芯片，再回头研究复用关系。

说明：不同开发板把 LED、按键接到哪些引脚并不固定，编写程序前必须先查看板子的电路原理图，找到每个 LED 和按键对应的端口编号，这一步决定了后面宏定义怎么写。

用 IAR8051 搭建第一个 CC2530 工程

CC2530 是 8051 内核，需要用支持 8051 的集成开发环境来编译，最常用的是 IAR Embedded Workbench for 8051（简称 IAR8051）。它和平时写桌面程序用的 IDE 有个明显区别：先建工作区，再在工程里添加源文件，新建的文件不会自动进入工程，需要手动添加。理解了这个逻辑，操作起来就顺了。

创建工作区与工程

  1. 打开软件，在菜单栏选择 File → New → Workspace，先建立一个工作区。工作区只是一个”容器”，此时磁盘上还看不到明显变化。
  2. 选择 Project → Create New Project，内核类型只能选 8051，模板选 Empty project（空工程），然后给工程起名字、指定保存路径。完成后，左侧工作区窗口会出现工程节点，磁盘上会多出一个 settings 文件夹。
  3. 配置芯片型号：在工程选项里进入 General Options → Target → Device information，从 Texas Instruments 目录下选择 CC2530F256。这一步决定编译器按照哪颗芯片的资源来分配内存。
  4. 配置仿真器：进入 Debugger → Setup → Driver，选择 Texas Instruments。这样下载程序时软件才能找到对应的调试驱动。

添加源文件并保存

新建 C 源文件有两种方式：一种是在工程上右键选择 Add → Add Files，在弹出的对话框右下角把文件类型切换成”全部文件”，然后新建一个后缀为 .c 的文件并选中它，这相当于”创建并导入”一步完成；另一种是点工具栏的新建按钮写一个空文件，按 Ctrl+S 保存成 .c 文件——注意，这种方式还要再右键工程把它添加进来，否则它只是躺在磁盘上，不会参与编译。建议文件名用英文，避免编码问题引发奇怪的编译错误。添加成功后，工程目录里会出现一个 Debug 文件夹，用来存放编译生成的中间文件。

最后选择 File → Save Workspace 保存工作区，会生成 .eww 文件。至此，磁盘上会出现四个后缀不同的文件，它们的分工如下：

文件后缀 作用
.eww 工作区文件，记录整个工作区包含哪些工程
.ewp 工程文件，保存编译选项、源文件列表等核心配置
.dep 依赖关系文件，记录源文件之间的依赖，供增量编译使用
.ewd 调试配置文件，保存断点、观察变量等调试信息

日常备份和迁移工程时，这几个文件要放在一起，只拷 .c 文件会导致配置全部丢失。

SEL、DIR、INP 三个寄存器怎么分工

端口的行为由一组特殊功能寄存器控制，初学阶段最常打交道的三个是 SEL、DIR、INP。它们分别管”功能、方向、模式”，职责完全不同，一定要分清。

寄存器 中文含义 取值含义 作用
SEL 功能选择 0 = 普通 IO，1 = 外设功能 决定引脚是当通用 IO 用，还是交给串口、定时器等外设
DIR 方向选择 0 = 输入，1 = 输出 决定引脚是往外输出电平，还是读取外部电平
INP 输入模式 配合上拉、下拉、三态 当引脚作输入时，决定它的电气连接方式

这里有一个非常常见的误解需要当面纠正：SEL 不负责输入或输出，它只决定引脚是普通 IO 还是外设功能；真正决定输入方向的寄存器是 DIR。 有些资料写成”SEL：0 为输入，1 为输出”，这是错误的，如果照着配置，引脚可能根本不会按预期工作。正确记法是：SEL 管”身份”，DIR 管”方向”，INP 管”输入时的电气模式”。

所以要点亮一盏 LED，需要两步：先把对应引脚通过 SEL 设成普通 IO，再通过 DIR 设成输出，然后往引脚写 1 或 0 控制亮灭；而读取按键时，则要把 DIR 设成输入，并用 INP 配置上拉或下拉。

第一个 CC2530 点灯程序

要解决什么：让接在 P1_0、P1_1、P1_3、P1_4 上的四盏 LED 全部点亮并保持。思路是先包含芯片头文件，给引脚起有意义的名字，再初始化端口方向，最后输出高电平。

代码里 0x1B 的二进制是 0001 1011，正好对应 P1_0、P1_1、P1_3、P1_4 四个位。&= ~0x1B 把这几位清成 0（设为普通 IO），|= 0x1B 把这几位置成 1（设为输出），其余位保持原样不受影响——这种”只动相关位”的写法是嵌入式开发的基本功。另外，标准 C 里 main 通常返回 int，而 8051 这里习惯写成 void main(void)，不带返回值。

预期效果：把程序下载到开发板后，四盏 LED 同时点亮并一直保持。如果灯不亮，先确认宏定义的引脚编号和板子电路图是否一致，再检查芯片型号是否选成了 CC2530F256。

把”选功能、定方向、写电平”这三步走通，就已经掌握了 CC2530 端口编程的核心套路。后面的点灯闪烁、按键检测、外部中断，本质上都是在这三步之上叠加延时、读取和中断逻辑，并没有新的难点。
