命令是和 Linux 对话的方式。刚上手时，最实用的不是把每个命令的所有参数背下来，而是知道”遇到某类事情，该用哪个命令、怎么写”。这一篇按使用场景把高频命令整理成速查手册，每条都给出语法、常用参数和可以直接复制的例子，用到时回来翻一翻就行。

文件与目录操作

这是每天都会用到的基础动作：显示位置、列目录、切换、新建、删除、复制、移动。先看清命令和参数：

命令 作用 常用参数
pwd 显示当前所在目录 无
ls 列出目录内容 -l 详细、-a 含隐藏、-h 易读大小、-t 按时间排序
cd 切换目录 .. 上一级、~ 家目录、- 上一个目录
mkdir 创建目录 -p 递归创建多级目录
rmdir 删除空目录 无
rm 删除文件或目录 -r 递归、-f 强制、-i 删除前确认
cp 复制文件或目录 -r 递归、-p 保留属性、-a 归档模式
mv 移动或重命名 无常用参数
touch 创建空文件或更新时间戳 -t 指定时间

要解决什么：在一台新机器上建立一套项目目录，把文件复制过去，再改个名。

这里有两个容易踩坑的地方。rm -rf 表示强制递归删除，威力很大且不会二次确认，执行前务必确认路径写对；cp -a 相当于 -dR --preserve=all，会保留权限、时间戳、链接等全部属性，做备份时比单纯的 -r 更合适。预期效果：执行后你能在正确的位置看到新建的目录和文件，复制件保留了原始属性。

文件内容查看

看文件内容也有讲究：小文件直接显示，大文件要分页，日志则常看开头或结尾。

命令 作用 常用参数
cat 连接并显示文件内容 -n 显示行号
more 分页显示，只能向下翻 空格翻页、q 退出
less 分页显示，可上下翻 b 上翻、/关键词 搜索、q 退出
head 显示文件开头 -n 20 指定行数
tail 显示文件结尾 -n 20 指定行数、-f 实时跟踪

要解决什么：查看一份很长的日志，先定位末尾的最新记录，再实时盯着它的变化。

less 比 more 更灵活，能前后翻页也能搜索，日常优先用它。tail -f 是排查运行故障的利器：日志一有新内容，终端就立刻显示出来。预期效果：你能快速从海量日志里找到最近的错误，而不必把整个文件翻一遍。

查找与搜索

“文件放哪了”和”内容在哪一行”是两个不同问题，分别用 find 和 grep。

命令 作用 常用参数
find 按名称、类型、大小、时间、用户查找文件 -name、-type、-size、-mtime、-user
grep 在内容里搜索匹配的行 -r 递归、-i 忽略大小写、-n 显示行号、-v 反向匹配

要解决什么：找出家里所有文本文件，再看其中哪些提到了某个关键词。

find 的条件可以组合，-type f 限定只找文件、-size +1M 表示大于 1MB、-mtime -7 表示 7 天内。grep 的 -v 是反向匹配，上面最后一条就常用来过滤掉注释和空行。预期效果：你能迅速定位目标文件，或在一堆日志中筛出真正关心的行。

压缩与解压

不同压缩格式用不同工具，Linux 上最常见的是 tar 包和 zip 包。

命令 作用 常用参数
tar 打包与解包 -c 创建、-x 解包、-z 用 gzip、-v 显示过程、-f 指定文件名、-t 查看内容
gzip / gunzip 压缩 / 解压单个文件 生成 .gz 文件
zip / unzip 创建 / 解压 zip 包 跨平台通用

要解决什么：把整个项目目录打包压缩备份，之后再解压还原。

tar 的参数看起来多，其实记住”c 创建、x 解压、z 用 gzip、f 跟文件名”这一组就够了，-czvf 和 -xzvf 是一对最常用的组合。需要保留权限做完整备份时，也可以加上 -p。预期效果：一条命令得到一个压缩包，需要时原样解开，目录结构和权限都不乱。

系统信息查看

机器卡不卡、磁盘够不够、内存剩多少，靠下面这些命令一目了然。

命令 作用 常用参数
uname 显示系统信息 -a 全部、-r 内核版本、-m 机器架构
df 查看磁盘剩余空间 -h 易读格式、-i inode 使用情况
du 查看目录/文件占用空间 -sh 显示总和、-ah 列出所有
free 查看内存使用 -h 易读格式
top / htop 动态监控进程与资源 htop 是增强版，需额外安装

要解决什么：磁盘报警了，先确认哪个分区满了，再找出是哪个目录在占用空间。

df 看的是”整个分区”的余量，du 算的是”某个目录”实际占了多大，两者配合才能定位空间去哪了。top 打开后能看到 CPU、内存占用最高的进程，按 q 退出。预期效果：你能判断是磁盘真满了还是 inode 耗尽，并揪出占用空间的大户。

进程管理

当某个程序卡死或占用过高，就需要查看和终止进程。

命令 作用 常用参数
ps 显示进程快照 aux 详细信息、-ef 完整格式、-u 指定用户
kill 按 PID 终止进程 -9 强制终止
killall 按名称终止一类进程 直接跟进程名
pkill 按名称匹配终止进程 支持模式匹配

要解决什么：找出卡死的浏览器进程并结束它。

kill 默认发送的是”请求退出”信号，给进程留出清理的机会；kill -9 是强制杀死，可能导致数据没来得及保存，应作为最后手段。ps aux 的输出里，第二列就是 PID。预期效果：卡住的进程消失，系统资源得到释放。

网络相关命令

排查网络问题时，先看连通性，再看地址和端口。

命令 作用 常用参数
ping 测试主机连通性 -c 4 只发 4 个包
ifconfig 查看网卡信息（较老） 无
ip 新一代网络配置工具 addr 看地址、route 看路由
netstat 查看网络连接与端口 -tuln 看监听端口、-r 看路由
ss socket 统计，推荐替代 netstat -tuln 看监听端口

要解决什么：确认本机 IP 是否正确、网站是否可达、某个服务的端口有没有监听。

新系统里 ifconfig 和 netstat 逐渐被 ip 和 ss 取代，功能更强、输出更清晰。比如要确认 Nginx 是否真的在 80 端口监听，用 ss -tuln | grep :80 一眼就能看出来。预期效果：网络不通时，你能逐层判断是 DNS、路由还是服务本身的问题。

踩坑小贴士：PATH 配错后的恢复

修改环境变量时不小心把 PATH 写坏，是很常见的翻车现场：明明命令还在，系统却提示 command not found，连 vi、sudo 都用不了。别慌，PATH 只是告诉系统去哪里找命令，临时重设一下就能恢复。

要解决什么：PATH 被改错后，临时恢复出一个可用的命令搜索路径，先把终端救回来。

这条命令把几个标准目录重新拼成 PATH：/bin、/sbin 放系统基础命令，/usr/bin、/usr/sbin 放常规程序，/usr/local/bin、/usr/local/sbin 放本地安装的软件。执行后，常用命令立刻就能找到了。

这里要提醒两点。第一，这是临时恢复，只对当前终端会话有效，关掉窗口就失效；要永久生效，得把正确配置写进 ~/.bashrc 或 ~/.profile，写之前一定先备份。第二，配置 PATH 时建议用 $PATH 追加而不是整体覆盖，比如 export PATH=$PATH:/your/new/path，这样就不会把系统原有路径弄丢。预期效果：终端从”什么命令都找不到”恢复到可用状态，你可以从容地去修正配置文件。
