智能水表、电表、烟感这些设备往往分布在地下室、管道井等信号不好的地方，还要靠电池工作好几年。NB-IoT（窄带物联网）正是为这类场景设计的：覆盖深、功耗低、连接多。主控芯片要让模组干活，靠的是一种非常古老却依然通用的语言——AT 指令。一条条文本命令通过串口发过去，模组就完成联网、连接服务器、收发数据等动作。

串口链路准备：先把话说明白

在发任何业务指令之前，得先确认串口通道是通的，并让模组进入一个”安静、可解析”的状态。模组厂商很多，比如利尔达、移远、SIMCOM、美格等，但下面这几条基础指令基本通用。

阶段 指令 作用 预期响应
测试链路 AT 探测模组是否上电并响应 OK 或回显 AT
关闭回显 ATE0 关闭串口回显，减少带宽占用和解析干扰 OK
开启回显 ATE1 调试初期可打开，发送什么就返回什么 OK
查询模组名称 AT+CGMM 读取模组型号，便于驱动兼容不同模组 返回模组名称字符串
获取 IMEI AT+CGSN 读取国际移动设备识别码，相当于模组身份证 返回 15 位 IMEI 号

这里有几个实务经验。模组启动时间因厂商而异，有的 cold start 要十几秒，开机后应周期性发送 AT，直到收到响应再继续，不要一上电就猛发指令。回显在开发初期开着方便调试，进入正式产品后要关掉，否则返回数据里混着命令本身，解析程序容易出错。IMEI 号要像身份证号一样妥善保管，NB-IoT 模组在连接 socket 前通常需要用它做认证。

网络注册：让模组真正入网

确认模组能对话后，接下来要检查 SIM 卡、信号质量和网络注册状态，并配置运营商参数。

阶段 指令 作用 预期响应
检测 SIM 卡 AT+CPIN? 查询 SIM 卡是否就绪 +CPIN: READY
查询信号强度 AT+CSQ 读取当前信号质量 +CSQ: 29,99
设置网络附着 AT+CREG=1 开启网络注册状态上报 OK
查询网络附着 AT+CREG? 查询是否已注册到网络 +CREG: 1,1 表示已注册
查询运营商 AT+COPS? 读取当前运营商信息，供下一步设 APN +COPS: 0,0,"CHN-TELECOM",7
设置 APN AT+QICSGP=1,1,"cmnet","card","card",3 配置接入点名称及账号密码 OK
查询本地 IP AT+CGDCONT? 确认是否已获取 IP 地址 +CGDCONT: 1,"IP","CMIOT","10.139.210.85",0,0
IMEI 认证 AT+EGMR=1,7,"123456789012345" NB 模组手动写入并认证 IMEI OK

AT+CSQ 返回的第一个数字是信号强度等级，取值范围 0 至 31，数值越大信号越好，99 表示未知；第二个参数是误码率。把这条指令放在空闲线程里周期性查询，可以监控设备所处的信号环境。

网络注册部分各厂商差异最大：AT+CREG 是参考写法，有的模组用 AT+CGREG 或 AT+CEREG，返回格式也可能略有不同，第二位为 1 通常表示已注册到本地网络，为 3 表示注册被拒绝。AT+COPS? 拿到的运营商信息主要用于下一步配置 APN，如果产品只用固定一家运营商的卡，这一步可以简化。

三大运营商 APN 对照

APN（接入点名称）是模组接入运营商移动网络的”大门”，不同运营商的设置不同。专网卡还需要运营商提供专门的用户名和密码。

运营商 非专网 APN
中国移动 cmnet
中国联通 3gnet
中国电信 ctlte

数据收发：建立 socket 并传数据

网络就绪后，就可以连接远端服务器并收发数据了。这一步同样存在明显的厂商差异，下面给出几种常见写法。

阶段 指令示例 作用 预期响应
建立连接 AT+MIPCALL=1 激活移动场景，建立网络连接 +MIPCALL:1,10.13.44.170
打开 socket AT+QIOPEN=1,1,"TCP","20.10.150.154",6201,10000,1 以 TCP 方式连接指定服务器和端口 OK
发送数据 AT+QISEND=... 把数据发到已建立的 socket OK 及发送确认
接收数据 无需指令，模组主动上报 模组主动输出带标识的数据帧 见下方 URC 帧格式
关闭 socket AT+QICLOSE=1 断开 socket 连接 OK

建立连接这一步有的模组不单独提供指令，而是和”打开 socket”合并完成；适合自己的模组，要以对应厂商的 AT 手册为准。发送数据时要注意数据格式：有的模组用同一条指令、通过配置在十六进制和 ASCII 码之间切换，有的则提供两条独立指令，写错格式服务器会收到乱码。

接收数据不用主动查询，模组会把网络数据主动输出到串口，这种带特定标识的上报叫 URC 帧，程序收到后解析出有效载荷即可。不同厂商的 URC 前缀不同：

厂商 接收数据 URC 示例
移远 +QIURC: "recv",1,20
SIMCOM +RECEIVE,1,20
美格 +MIPRTCP=1,20

把上面三个阶段串起来，NB-IoT 模组的完整拨号顺序是：测试串口链路 → 关闭回显 → 查询模组名称 → 获取 IMEI → 检测 SIM 卡 → 查询信号强度 → 设置网络附着 → 查询网络附着 → 查询运营商 → 设置 APN → 查询本地 IP → IMEI 认证 → 建立连接 → 打开 socket → 收发数据 → 关闭 socket。实际调试时建议逐条发送、逐条确认响应，哪一步卡住就重点排查那一步——比如拿不到 IP 先查 APN 和信号，连不上服务器先查 IP 和端口。等整条链路稳定跑通，设备数据就能顺利到达云端了。
