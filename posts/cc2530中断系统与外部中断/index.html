想象你正在看书，手机突然响了。你可以每读一页就抬头看一眼手机有没有消息——这叫轮询；也可以把手机调成响铃模式，来电话时它主动提醒你，你放下书去接，接完再回来接着看——这叫中断。CC2530 处理外部事件时，用的就是后一种思路：平时主程序按自己的节奏运行，一旦按键按下、数据到达或者定时时间到，硬件就”打断”它，让它先处理紧急事件，处理完再回来。

轮询与中断：两种方式谁更省心

轮询的方式是主程序反复查询某个标志位，看看事件发生了没有。写法简单，但 CPU 得一直盯着，哪怕事件半天不发生也不能歇着，大量时间浪费在”查看”上。中断则相反：事件发生时由硬件自动置位标志并通知 CPU，CPU 暂停当前工作，跳到一段专门的函数去处理，处理完再回到原来的位置继续。

对比项 轮询 中断
CPU 占用 一直查询，占用高 事件驱动，空闲时可休眠
响应速度 取决于查询频率，可能延迟 硬件响应，及时
编写难度 简单直观 需要配置寄存器和中断函数
适用场景 简单、事件不频繁的任务 按键、通信、定时等实时性要求高的场合

对电池供电的物联网节点来说，中断还有个额外好处：CPU 可以在没事件时进入低功耗模式，靠中断唤醒，从而大幅延长续航。

中断向量与中断服务函数

CC2530 一共有 18 个中断源。每个中断源对应一个固定的入口地址，称为中断向量（也叫中断指针）。当某个中断被响应时，CPU 会自动跳到这个地址去执行相应的处理代码。这些向量名和地址都定义在 ioCC2530.h 头文件里，常用的一部分如下：

中断向量名 入口地址 触发事件
RFERR_VECTOR 0x03 射频发送 FIFO 下溢、接收 FIFO 溢出
ADC_VECTOR 0x0B ADC 转换结束
URX0_VECTOR 0x13 USART0 接收完成
P2INT_VECTOR 0x33 端口 2 有引脚产生外部中断
UTX0_VECTOR 0x3B USART0 发送完成
T1_VECTOR 0x4B 定时器 1 捕获、比较或溢出
P0INT_VECTOR 0x6B 端口 0 有引脚产生外部中断
P1INT_VECTOR 0x7B 端口 1 有引脚产生外部中断
RF_VECTOR 0x83 射频通用中断
WDT_VECTOR 0x8B 看门狗定时器模式溢出

向量号（也就是入口地址）越小，优先级越高；每个向量名对应一个固定的内存位置。实际编程时我们只管写向量名，不用手写十六进制地址。

外部中断涉及的寄存器

CC2530 的 P0、P1、P2 每个引脚都具备外部中断输入能力，但要真正用起来，需要好几组寄存器配合。它们可以分成”使能””触发方式””标志”三类：

寄存器 中文含义 作用
IEN0、IEN1、IEN2 中断使能寄存器 0/1/2 各中断源的使能开关，总开关 EA 在 IEN0 的最高位
P0IE、P1IE、P2IE 端口中断使能位 使能整个端口的中断，P1IE 位于 IEN2 的第 4 位
P0IEN、P1IEN、P2IEN 引脚中断使能寄存器 选择端口里具体哪几个引脚可以产生中断
PICTL 端口中断控制寄存器 设定中断触发沿为上升沿还是下降沿
P0IFG、P1IFG、P2IFG 引脚中断标志寄存器 记录具体是哪个引脚触发了中断，需手动清除
P0IF、P1IF、P2IF 端口中断标志位 端口级的汇总标志，需手动清除
EA 总中断使能位 相当于整个中断系统的总开关，EA = 1 打开

外部中断的触发方式分两种：上升沿指信号从低电平跳到高电平的瞬间，例如按键松开时；下降沿指信号从高电平跳到低电平的瞬间，例如按键按下时。PICTL 负责选择这个边沿，其中第 0 位控制 P0 端口，第 1 位控制 P1 端口的低四位（P1_0 到 P1_3），第 2 位控制 P1 端口的高四位（P1_4 到 P1_7），第 3 位控制 P2 端口。统一规定 0 表示上升沿，1 表示下降沿。

明白了这些寄存器，外部中断信号从产生到被响应的完整链路就可以用下面的顺序描述：

  1. 引脚上出现上升沿或下降沿信号；
  2. 硬件拿这个信号和 PICTL 中设定的触发沿比对，一致才继续；
  3. 对应引脚在 PxIFG 中的标志位被自动置 1；
  4. 信号经过 PxIEN 筛选，确认这个引脚确实开了中断；
  5. 以上条件都满足后，端口标志 PxIF 被置 1，向 CPU 提出中断请求；
  6. CPU 响应中断，根据中断向量找到服务函数；
  7. 服务函数查询 PxIFG，判断到底是哪个引脚触发的，然后执行对应处理。

标志位清除顺序：先 PxIFG，再 PxIF

这是外部中断里最容易出错、后果又最明显的一个细节。中断标志必须在中断服务函数里手动清除，否则 CPU 看到标志一直有效，就会反复进入中断，程序看起来像”卡死”了一样。

清除时还有严格的先后要求：先清引脚标志 PxIFG，再清端口标志 PxIF。原因在于 PxIF 是端口级的汇总标志，只要 PxIFG 里还有任何一个引脚标志没清掉，硬件就认为该端口仍有未处理的中断，会重新把 PxIF 置起来。如果反过来先清 PxIF，等于白清一次，程序照样会反复进中断。记住一句话：先细后粗，先引脚后端口。

完整外部中断例程

要解决什么：用 P1_2 上接的按键作为外部中断源，按下时翻转 LED 的状态。相比上一章的按键扫描，中断方式不需要主程序一直循环查询，CPU 可以更”悠闲”。

预期效果：每次按下按键，LED3 的亮灭状态翻转一次，主循环不需要任何按键查询代码。如果按一次却连续翻转多次，多半是标志位清除顺序写反了，或者忘了清除标志；如果完全没反应，则按”总开关 EA → 端口使能 P1IE → 引脚使能 P1IEN → 触发沿 PICTL”的顺序逐项检查。

至此，按键事件已经能主动”叫醒”CPU 了。如果把触发源从引脚电平变化换成定时器溢出，就是下一章要讲的定时器中断——两者的寄存器思路一脉相承，只是中断向量和标志位换成了定时器那一套。
