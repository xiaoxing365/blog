会敲单条命令，只能算”会用” Linux；把命令组合起来处理文本、管理服务、定时运行任务，才算真正”用好”。这一篇就从编辑文本开始，一路讲到服务、定时任务、日志和 Shell 的三个基础机制。每一处都按”场景 + 命令 + 结果”的方式来写，照着做就能看到效果。

vim：终端里的文本编辑器

vi 是 Linux 上历史最悠久的文本编辑器，几乎每台机器都有。vim 是 vi 的增强版，支持语法高亮、多级撤销等特性，日常使用它和 vi 的方式基本一致；neovim（nvim）则是 vim 的现代分支，体验更流畅。掌握 vim，你在任何终端里都能从容改文件。

三种模式是理解 vim 的钥匙

新手觉得 vim 难，多半是因为没搞清楚模式。vim 主要有三种模式：

  • 命令模式（普通模式）：打开文件后默认进入。在这个模式下，按键代表操作命令，比如移动光标、删除、复制、粘贴，而不是往文件里写字。
  • 插入模式：在命令模式下按 i、a、o 等键进入，此时才能正常输入和编辑文字。按 Esc 回到命令模式。
  • 末行模式（命令行模式）：在命令模式下按 : 进入，光标跳到屏幕底部，用来执行保存、退出、搜索、替换等命令。

记住一条主线：打开文件 → 命令模式 → 按 i 进入插入模式改内容 → 按 Esc 回命令模式 → 按 : 输入 wq 保存退出。

场景：编辑一份配置文件，改完后保存退出。

进入后按 i 开始改，改完按 Esc，再输入 :wq 回车。

结果：文件被保存，vim 退出回到终端。如果只想退出不保存，用 :q!；只想保存不退出，用 :w。

高频快捷键速查

下面这些按键都在命令模式下使用，整理成表格方便记忆：

按键 作用
i / a 在光标前 / 光标后进入插入模式
o 在光标下方新开一行并进入插入模式
s 删除光标处字符并进入插入模式
Esc 从插入模式返回命令模式
gg / G 跳到文件第一行 / 最后一行
:数字 跳到指定行，如 :50 跳到第 50 行
h j k l 光标左、下、上、右移动
v → 选中 → y → p 可视模式选中文字，复制后粘贴
/关键词 向下搜索关键词，按 n 跳到下一个
dd / yy 删除 / 复制当前行
:wq / :q! 保存退出 / 强制退出不保存

场景：想选中一段文字，复制后粘到文件末尾。

结果：选中的文字被复制到文件末尾。熟练之后，光标移动、选中、复制、粘贴可以一气呵成，编辑效率远超鼠标操作。

sed：按行处理文本的流编辑器

sed 擅长对文本做批量替换、删除、打印，尤其适合处理大文件或在脚本里自动改写内容，不必打开文件逐行手动改。

写法 作用
sed 's/old/new/g' 文件 把每行中的 old 全部替换成 new
sed -n '5,10p' 文件 只打印第 5 到 10 行
sed '/pattern/d' 文件 删除匹配 pattern 的行
sed -i 's/old/new/g' 文件 直接写回文件（谨慎使用）

场景：把配置文件里所有的 localhost 换成 127.0.0.1，并先预览再写回。

结果：第一次执行只在屏幕上显示替换后的内容，app.conf 本身没变；第二次执行后，文件里的 localhost 全部被替换。s 是替换命令，结尾的 g 表示全局替换（否则每行只替换第一处）。-i 会直接改文件，建议先用不带 -i 的命令预览，确认正确再写回。

awk：按列处理文本的利器

如果说 sed 按”行”处理，awk 更擅长按”列”处理。它会把每行按分隔符切成若干字段，$1 表示第一列，$2 表示第二列，$0 表示整行。

写法 作用
awk '{print $1}' 文件 打印每行的第一列
awk -F: '{print $1}' /etc/passwd 以冒号为分隔符，打印第一列
awk '/pattern/ {print $0}' 文件 打印匹配 pattern 的整行

场景：从 /etc/passwd 里列出所有用户名。这个文件用冒号分隔字段，用户名在第一列。

结果：终端逐行输出系统里的用户名，如 root、daemon、alice。-F: 指定冒号为分隔符（默认是空格或制表符），{print $1} 表示打印第一列。再比如 awk -F: '$3==0 {print $1}' /etc/passwd 可以找出 UID 为 0 的账户，也就是拥有 root 权限的用户，这在安全排查时很有用。

sort 与 uniq：排序和去重

这两个命令常配合管道使用，用来整理杂乱的数据。

命令 作用 常用参数
sort 按行排序 -r 反向、-n 按数值、-u 排序并去重
uniq 去除连续的重复行 -c 统计重复次数

场景：统计一份访问日志里，哪个 IP 出现得最多。

结果：输出出现次数最多的前 5 个 IP，每行前面带一个数字表示次数。

这一条命令串起了好几个工具：先用 awk 取出第一列（IP），再用 sort 把相同 IP 排到一起（uniq 只能去掉相邻的重复行，所以必须先排序），接着 uniq -c 统计每个 IP 的出现次数，最后 sort -rn 按数字反向排序，把次数多的排在最前，head -n 5 取前五名。这就是 Linux “小工具组合”思想的典型体现。

systemctl：服务管理

现代 Linux 用 systemd 作为初始化系统，systemctl 是管理服务的统一命令，适用于 CentOS 7+ 和 Ubuntu 16+。

命令 作用
systemctl start 服务名 启动服务
systemctl stop 服务名 停止服务
systemctl restart 服务名 重启服务
systemctl status 服务名 查看服务状态
systemctl enable 服务名 设置开机自启
systemctl disable 服务名 取消开机自启

场景：修改 Nginx 配置后，让它重新加载并确认运行正常。

结果：status 的输出里出现绿色的 active (running)，说明服务正常运行。注意 restart 只影响当前运行，enable 才决定下次开机是否自动启动，两者是独立的，别混淆。

crontab：让任务按时自动运行

crontab 用来设置周期性执行的任务，比如每天凌晨备份、每五分钟检查一次服务。

命令 作用
crontab -e 编辑当前用户的定时任务
crontab -l 列出已有任务
crontab -r 删除当前用户的所有任务（慎重）

每条定时任务由五个时间字段加一条命令组成，格式如下：

从左到右依次是：分钟、小时、日期、月份、星期。* 表示”每一个”，也就是该字段不限制。

场景：每天凌晨 2 点执行备份脚本，另外每 5 分钟检查一次服务。

结果：保存退出后任务即生效。第一行的 0 2 * * * 表示每天 2 点 0 分执行；第二行的 */5 表示”每 5 分钟”。可以用 crontab -l 随时查看已设置的任务。需要注意，定时任务里的命令最好写绝对路径，因为 cron 执行时的环境变量和你登录时不一样，找不到命令是常见故障。

系统日志：出了问题去哪里查

日志是排查问题的第一现场。Linux 的日志主要放在 /var/log 目录：

日志文件 内容
/var/log/messages 系统主要日志（CentOS）
/var/log/syslog 系统日志（Ubuntu）
/var/log/auth.log 认证相关日志（Ubuntu）
/var/log/secure 安全与认证日志（CentOS）

在使用 systemd 的系统上，还可以用 journalctl 统一查看日志：

命令 作用
journalctl -f 实时跟踪最新日志
journalctl -u 服务名 查看指定服务的日志
journalctl --since "2026-11-20" 查看指定时间之后的日志

场景：Nginx 服务启动失败，想看看它到底报了什么错。

结果：终端显示 Nginx 服务在这段时间内的日志，通常能直接看到错误原因，比如端口被占用或配置文件语法错误。配合 -f 实时跟踪，还能观察服务重启时的动态输出。

Shell 基础：把命令串起来的三个机制

最后看三个让命令变得”可编程”的基础机制：环境变量、重定向和管道符。

环境变量

环境变量是系统或 Shell 保存的一组”设置值”，程序运行时会读取它们。PATH 是最典型的一个，它决定了系统去哪些目录找命令。

命令 作用
echo $PATH 显示 PATH 的内容
export 变量=值 设置并导出环境变量
unset 变量 删除环境变量
source 文件 让修改后的配置立即生效

场景：临时给 PATH 增加一个自定义脚本目录。

结果：该目录加入命令搜索路径，你可以直接运行里面的脚本。用 $PATH 追加而不是覆盖，能保留原有路径。要永久生效，把这一行写进 ~/.bashrc，再执行 source ~/.bashrc。

输入输出重定向

重定向用来改变命令的输入来源和输出去向，是处理文本和保存结果的基础。这部分的符号也叫左右移定向符。

写法 作用
命令 > 文件 标准输出写入文件（覆盖原有内容）
命令 >> 文件 标准输出追加到文件末尾
命令 < 文件 从文件读取标准输入
命令 2> 文件 把错误信息写入文件
命令 > 文件 2>&1 把正常输出和错误信息一起写入文件

场景：把命令的完整输出（包括报错）保存到日志文件，方便事后查看。

结果：终端不再显示输出，所有内容都进了 result.log。其中 2>&1 的意思是”把标准错误（文件描述符 2）合并到标准输出（文件描述符 1）”，这样无论成功还是失败的信息都不会漏掉。用 > 会覆盖文件，用 >> 则是追加。

管道符

管道符用竖线 | 表示（在键盘上由 Shift 加上反斜杠键输入），作用是把左边命令的输出，作为右边命令的输入。它能把多个简单命令串成一条强大的处理流水线。

场景：列出当前目录的所有文件，并从中筛出名字带 mysql 的。

结果：终端只显示文件名里包含 mysql 的条目。ls 的输出本来会直接显示在屏幕上，加上管道后，这些内容转而交给 grep 去过滤。前面统计 IP 的那条命令，就是把 awk、sort、uniq、head 用管道串起来的例子。管道符是 Linux 组合命令的核心，掌握它，你就能把一个个简单工具拼出复杂功能。

从 vim 改配置，到用 sed、awk 批处理文本，再到用 systemctl 管服务、crontab 定时、日志排查问题，最后用环境变量、重定向和管道把命令串起来——这些技能拼在一起，就是你从”会敲命令”走向”能自动化运维”的完整路径。剩下的，就是在真实场景里反复用、反复练。
