一、聚合函数：一条语句算出一组数据的统计值

用过 WPS 表格的人对”求和、计数、平均值”一定不陌生，MySQL 里把这些能力做成了内置函数，直接写在 SELECT 后面就能用。函数不改变表里的原始数据，只是对查出来的结果做加工。

为了方便演示，先建一张销售流水表并塞几条数据。

1.1 五个核心聚合函数速查

函数 作用 示例
COUNT() 统计行数；COUNT(*) 统计所有行，COUNT(列) 忽略 NULL SELECT COUNT(*) FROM sales;
SUM() 求某一列的合计值，只对数值列有意义 SELECT SUM(amount) FROM sales;
MAX() 取某一列的最大值 SELECT MAX(amount) FROM sales;
MIN() 取某一列的最小值 SELECT MIN(amount) FROM sales;
AVG() 计算某一列的平均值 SELECT AVG(amount) FROM sales;

1.2 一次算出多个统计指标

要解决什么：做销售日报时，往往不是只要一个总数，而是同时要订单量、总额、最高最低单价和平均单价。逐个函数分开查要连数据库四次，写在一起只需一次。

预期效果：返回一行五列，分别是 4、2126.00、1299.00、129.00、531.50 左右（平均值随数据而定）。这就是聚合函数最典型的用法：把多行”压缩”成一行汇总结果。

预期效果：每个 category 输出一行。如果想在末尾追加总计行，在 GROUP BY 后面加 WITH ROLLUP 即可。

一个容易踩的细节：COUNT(*) 统计所有行，而 COUNT(amount) 会跳过 amount 为 NULL 的行。需要”总行数”时用 COUNT(*)，需要”有效值个数”时才用 COUNT(列)。

二、窗口函数 row_number() over()：保留每一行再排名

聚合函数好用，但它会把多行揉成一行。有时候你既想给每行编号或排名，又不想丢掉明细，这就需要窗口函数。MySQL 从 8.0 开始支持窗口函数，5.7 没有这个功能。

2.1 语法拆解

  • ROW_NUMBER()：给结果集的每一行生成一个从 1 开始、连续且不重复的序号。
  • PARTITION BY：把数据切成若干”窗口”，编号在每个窗口内重新从 1 开始；不写就等于整张表是一个窗口。
  • ORDER BY：决定编号的先后次序，这一步不能省。

2.2 解决”每组取第一名”这类问题

要解决什么：假设要找出每个品类里单价最高的那件商品。用 GROUP BY category 配合 MAX(amount) 只能拿到金额，拿不到对应的商品名；用窗口函数先 ranking，再筛出第 1 名，明细就完整保留了。

预期效果：每个品类只返回金额最高的那一行。这里 PARTITION BY category 让外设品类内部独立编号，ORDER BY amount DESC 让贵的排前面。如果去掉 PARTITION BY，就变成全表统一排名。

GROUP BY 与窗口函数的区别可以这么记：

对比 GROUP BY + 聚合函数 row_number() over()
结果行数 每组压缩成一行 原始行一行不少
能否看到明细 看不到被聚合掉的行 每行都保留，并多出一列编号
典型用途 统计总数、平均值 排名、分组取前 N 条、去重

顺带一提，ROW_NUMBER() 也常用来去重：按某字段分区、按时间倒序编号，然后删掉 rn > 1 的重复行，比传统的 GROUP BY + 子查询 直观得多。

三、常用字符串函数速查

处理文本是另一大类需求。下面这张表按”函数 → 作用 → 示例”整理，示例里的 s 表示字符串参数。

函数 作用 示例 返回值说明
ASCII(s) 返回字符串 s 第一个字符的 ASCII 码 SELECT ASCII('A'); 65
CHAR_LENGTH(s) 返回字符串 s 的字符数 SELECT CHAR_LENGTH('你好'); 2
CHARACTER_LENGTH(s) 同 CHAR_LENGTH，是它的同义词 SELECT CHARACTER_LENGTH('hi'); 2
CONCAT(s1,s2,…) 把多个字符串合并成一个 SELECT CONCAT('My','SQL'); MySQL
LENGTH(s) 返回字符串 s 的字节数 SELECT LENGTH('你好'); 在 utf8mb4 下是 6
LOWER(s) 把字符串全部转成小写 SELECT LOWER('HELLO'); hello
UPPER(s) 把字符串全部转成大写 SELECT UPPER('hello'); HELLO
SUBSTRING(s,pos,len) 从 pos 位置起截取 len 个字符 SELECT SUBSTRING('MySQL',2,3); ySQ
TRIM(s) 去掉字符串首尾空格 SELECT TRIM(' hi '); hi
REPLACE(s,a,b) 把 s 中的 a 全部替换成 b SELECT REPLACE('a-b','-','_'); a_b
LEFT(s,n) / RIGHT(s,n) 取最左/最右的 n 个字符 SELECT LEFT('MySQL',2); My

要解决什么：报表里经常需要把多列拼成一个展示字段，或者从一段文本里截取固定位置的内容，字符串函数能直接在 SQL 层完成，不必把数据拉回程序再处理。

预期效果：输出形如 键盘 [外设] 的标签列和对应字符数。注意 CHAR_LENGTH 数的是”字符”，LENGTH 数的是”字节”；在 utf8mb4 下一个中文字符占 3~4 个字节，所以 CHAR_LENGTH('你好') 是 2，LENGTH('你好') 往往是 6。需要按人的直觉统计字数时用 CHAR_LENGTH。

四、视图：把复杂查询封装成”虚拟表”

4.1 视图到底是什么

视图可以想象成窗户上的一层定制贴膜：你透过它看到的是窗外的景色，但景色本身并不在贴膜上。技术上说，视图是一个虚拟表——它的内容由一条 SELECT 查询定义。数据库里只保存视图的定义（那条 SQL），并不保存视图的数据；真正的数据仍然存在原来的表（也叫基表）里。当你查询视图时，数据库系统临时从基表中取出对应数据呈现给你。

因此有两个重要推论：基表数据变了，视图看到的结果会跟着变；反过来，在满足一定条件时，对视图做 UPDATE、INSERT 也会影响到基表。视图不是数据副本，而是一层”查询视角”。

4.2 视图的四大作用

  1. 简化操作。把多表 JOIN、复杂 WHERE、分组统计封装成一句 SELECT * FROM 视图名，业务代码不用每次重复一长串 SQL。
  2. 增加数据安全性。只把允许看的列暴露给视图，比如给客服的视图里不放身份证号和工资，隐藏敏感数据。
  3. 提高表的逻辑独立性。基表结构变化时，可以调整视图定义来适配旧接口，外部查询不必跟着改，相当于加了一层隔离。
  4. 统一查询口径。所有人都从同一个视图取数，避免各写各的 SQL 导致统计口径不一致。

4.4 修改与删除视图

预期效果：ALTER VIEW 改变的是视图的定义而非数据，DROP VIEW 删除的也只是定义，基表和其中的数据完全不受影响。这里要区分两个”删除”：DROP 删的是表或视图这样的对象，而 DELETE FROM 表名 WHERE ... 删的是表里的数据行——前者连结构一起消失，后者只清内容。

执行 SHOW TABLE STATUS 时，表和视图会一起列出来，通过 Comment 列可以区分：视图的 Comment 显示为 VIEW。

4.5 使用视图的几个注意事项

  • 视图名不能和同一库里的表名重名，否则创建会失败。
  • 包含聚合函数、DISTINCT、GROUP BY、UNION 或涉及多表的视图，通常是不可更新的，只能用来查询，别指望通过它改基表。
  • 视图本身不提供性能加速。复杂视图每次被查询都要执行背后的 SELECT，嵌套多层视图反而可能变慢，必要时可以用物化汇总表替代。
  • 权限要单独管理：视图定义者拥有访问基表的权限，但使用视图的人只需要有视图的查询权，这正是视图能隐藏敏感数据的原因。

小结

函数负责”加工数据”：COUNT、SUM、MAX、MIN、AVG 把多行聚成一行统计，row_number() over() 在不丢明细的前提下分组编号和排名，ASCII、CHAR_LENGTH、CONCAT 等字符串函数处理文本拼接与截取。视图负责”封装查询”：它只存定义不存数据，却能简化操作、隐藏敏感列、隔离基表变化。实际项目里两者常常搭配——把带聚合函数或窗口函数的复杂查询做成视图，上层应用只面对一张干净的”虚拟表”，既好维护也更安全。
