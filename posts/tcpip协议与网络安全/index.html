两台电脑隔着几千公里聊天，靠的不是魔法，而是一套层层分工的”邮政系统”。数据从应用里出发，被一层层打包、贴上标签，经过网线、光纤、路由器到达对方，再一层层拆开还原。这套系统中的规则就是协议，而理解协议的分层与连接管理，是读懂网络的第一步。

一、OSI 七层模型与 TCP/IP 体系

国际标准化组织（ISO）定义了 OSI 参考模型，目的是让不同厂商的设备能互相协作。它把通信过程分成七层，上层依赖下层，下层为上层提供服务。

层级 名称 传输单元（PDU） 主要职责 典型协议
7 应用层 数据 为应用程序提供网络服务 HTTP、FTP、DNS、SMTP
6 表示层 数据 加密解密、格式转换、压缩 SSL/TLS、JPEG
5 会话层 数据 建立、管理、维护会话 会话控制
4 传输层 数据段 segment 端到端连接、可靠传输、流量控制 TCP、UDP
3 网络层 数据包 packet IP 寻址、路由选择、分组转发 IP、ICMP、ARP
2 数据链路层 数据帧 frame MAC 寻址、组帧、差错控制 以太网、PPP
1 物理层 比特 bit 传输 0/1 电信号、定义接口特性 RJ45、光纤

封装是理解分层的关键：发送方每层都把上层交下来的内容当作”数据”，加上自己的头部再交给下一层。接收方则反过来，逐层剥掉头部还原原始数据。

实际的 TCP/IP 体系是 OSI 模型的简化落地，通常分为四层：网络接口层（对应物理层 + 数据链路层）、网络层（IP）、传输层（TCP/UDP）、应用层（对应会话层 + 表示层 + 应用层）。我们平时说的”TCP/IP 协议族”，指的就是这一整套协议集合。

二、建立连接：TCP 三次握手

TCP 是面向连接的协议，传数据之前必须先”打个电话”确认双方都在。这个过程叫三次握手，对应一个很生活化的场景：

甲：”喂，能听到吗？”（SYN）
乙：”能听到，你那边能听到我吗？”（SYN + ACK）
甲：”能听到，那我们开始说吧。”（ACK）

为什么必须是三次？两次不够吗？假设只有两次：客户端发出 SYN，服务器回了一个 SYN + ACK，服务器就认为连接建立了。但如果这个确认包在网络中丢失，客户端根本不知道，服务器却已经为这条连接分配了资源，会造成资源浪费。第三次握手让客户端再确认一次，双方都确认”对方能收能发”，连接才真正可靠。

三、断开连接：TCP 四次挥手

这里要特别区分两个容易混淆的说法：“握手”是建立连接，共三次；”挥手”是断开连接，共四次。因为 TCP 是全双工的，双方都能同时发数据，关闭连接时要各自把两个方向的通道都关掉。

甲：”我说完了，我要挂了。”（FIN）
乙：”好，我知道了。”（ACK）
乙：”等下，我把剩下的话也说完……说完了，我也挂了。”（FIN）
甲：”好的，再见。”（ACK）

为什么 ACK 和 FIN 没有合并成一次？ 因为服务器收到客户端的 FIN 时，内核会立刻回一个 ACK，但服务器自己的数据可能还没发完，只能等应用程序调用关闭动作后再发 FIN。一个是系统自动触发，一个是应用主动触发，时机不同，所以分成两次。

为什么客户端要进入 TIME_WAIT 等待？ 因为最后一次 ACK 可能丢失。如果服务器没收到，会重发 FIN，客户端需要留在 TIME_WAIT 状态重新回应。等待 2MSL（报文最大生存时间的两倍）能确保双方都干净地关闭，也避免旧连接的数据包干扰新连接。

四、IP 报头字段速查

数据在网络上传输时，每个数据包前面都带一个 IP 报头，长度通常是 20 字节（不含可选字段）。主要字段如下：

字段 位数 作用
版本 Version 4 标识 IP 版本，IPv4 为 4
首部长度 IHL 4 报头长度，以 4 字节为单位，通常 20~60 字节
服务类型 ToS 8 用于区分服务优先级（QoS）
总长度 Total Length 16 报头 + 数据的总字节数，最大 65535
标识 Identification 16 分片时用于重组
标志 Flags 3 标记是否允许分片、是否还有后续分片
片偏移 Fragment Offset 13 分片在原数据中的位置
生存时间 TTL 8 每经过一个路由器减 1，减到 0 就丢弃，防止无限循环
协议 Protocol 8 上层协议号，TCP=6，UDP=17，ICMP=1
首部校验和 16 检查报头在传输中是否出错
源 IP 地址 32 发送方地址
目的 IP 地址 32 接收方地址

TTL 是排查网络问题的好帮手：tracert（Windows）或 traceroute（Linux）就是利用 TTL 逐次加 1、让沿途路由器返回超时消息，从而画出数据包经过的路径。

五、常见协议对比：TCP、UDP、ICMP、ARP、TLS

协议 所在层 连接特性 可靠性 是否用端口 典型用途
TCP 传输层 面向连接，三次握手 可靠，不丢包，有重传 是 网页、文件传输、数据库
UDP 传输层 无连接，直接发送 不保证送达，速度快 是 语音视频、DNS 查询
ICMP 网络层 无连接 用于测试与差错报告 否 ping、traceroute
ARP 网络层 无连接 地址解析 否 由 IP 查 MAC 地址
TLS 会话层/应用层 建立在 TCP 之上 加密、身份认证 依赖 TCP 端口 HTTPS、安全邮件

TCP 与 UDP 怎么选？ TCP 像挂号信，一定会送到，但流程繁琐、延迟较高，适合下载文件、浏览网页、数据库访问；UDP 像广播，发出去就不管了，但延迟低、开销小，适合语音通话、直播推流这类”偶尔丢一两个包也能接受”的场景。

端口是区分同一台电脑上不同服务的编号，范围 065535。01023 是系统保留端口：

端口 服务 协议
80 HTTP 网页 TCP
443 HTTPS 加密网页 TCP + TLS
22 SSH 远程登录 TCP
21 FTP 文件传输 TCP
23 Telnet 远程登录 TCP
3389 Windows 远程桌面 RDP TCP
3306 MySQL 数据库 TCP
1433 SQL Server 数据库 TCP
445 Windows 文件共享 SMB TCP

到了应用层，TLS（传输层安全协议） 及其前身 SSL 负责给通信加密。HTTPS 就是 HTTP over TLS，浏览器通过证书验证服务器身份，再用对称加密传输数据，中间人即使截获也看不懂内容。TLS 与 SSL3.0 在加密算法和告警机制上不同，两者不能互操作，可以把 TLS 看作 SSL 的升级版。

六、常见欺骗的原理与防范

下面只讨论原理和防护思路，不涉及具体实施方法。理解攻击为什么能成立，才能知道该怎么防。

ARP 欺骗：冒领快递的”假门卫”

原理：ARP 协议用来把 IP 地址解析成网卡的 MAC 地址。设计之初没有身份验证机制，设备收到 ARP 应答就更新本地缓存。攻击者伪造应答，宣称”网关的 IP 对应我的 MAC”，局域网内其他设备就会把本该发给网关的数据送给攻击者，形成”中间人”。数据经过攻击者转发，看似正常通信，实则已被窥探。

防范思路：

  • 在关键设备上配置静态 ARP 绑定，固定 IP 与 MAC 的对应关系。
  • 使用交换机的 DHCP Snooping 与动态 ARP 检测功能，只放行合法绑定。
  • 对通信内容做加密（如全站 HTTPS），即使被截获也无法解读明文。
  • 部署内网 ARP 防护工具，发现异常广播及时告警。

DHCP 欺骗：私设的”发号窗口”

原理：DHCP 负责给接入设备分配 IP、网关和 DNS。如果局域网里出现一台未经授权的 DHCP 服务器，它可能给客户端分配错误的网关或恶意 DNS 地址，把流量引向可控节点，进而诱导用户访问仿冒站点。

防范思路：

  • 在交换机上启用 DHCP Snooping，只允许信任的上联端口发送 DHCP 应答。
  • 限制端口下挂设备数量，异常接入及时告警。
  • 客户端核对分配到的网关和 DNS 是否属于本单位规划的地址段。

DNS 欺骗：被篡改的”电话簿”

原理：DNS 把域名解析成 IP。若解析结果被篡改，用户输入正常域名却被导向恶意服务器，一旦在上面输入账号密码就会泄露。DHCP 欺骗常被用来下发恶意 DNS，两者经常配合出现。

防范思路：

  • 使用可信的递归 DNS 服务，必要时启用 DNSSEC 对解析结果做签名验证。
  • 采用 DoH/DoT 等加密 DNS 协议，防止解析请求被监听或篡改。
  • 浏览器严格校验证书，遇到证书告警不要跳过。
  • 重要站点使用 HTTPS，并留意域名拼写是否正确。

小结

OSI 七层模型提供了理解网络的框架，TCP/IP 是它的落地实现。记住两组关键数字：三次握手建立连接，四次挥手断开连接；握手确认双方收发能力，挥手因为全双工要分两次关闭。IP 报头里的 TTL、协议号、总长度字段，是排查问题的常用抓手。协议选型上，要可靠选 TCP，要低延迟选 UDP。最后，ARP、DHCP、DNS 的设计都缺少足够的身份认证，因此欺骗类问题防不胜防——最稳妥的策略是”绑定 + 加密 + 校验”三管齐下。
